# ユニットテスト計画・実行記録

一般 UT（セキュリティ専用計画ではない）の **計画** と **実行記録** を置く場所。

ルール: `.cursor/rules/ut-plan-go-api.mdc`

## 構成

```text
docs/ut/
  README.md
  plans/          # コンテキスト単位の計画（正本・更新可）
  runs/           # 実行のたびに日付付きで追加
    _TEMPLATE.md  # 実行記録のひな形（コピーして使う）
```

| 置き場 | 残すもの | 運用 |
| --- | --- | --- |
| `plans/` | 責務リスト＋ケース表 | コンテキスト名の Markdown（例: `message.md`） |
| `runs/` | 実行記録（ケース表＋結果） | `YYYY-MM-DD-<context>.md`。`_TEMPLATE.md` はコピー元 |

実行記録の結果表は、計画の列（目的・入力・依存の戻り・期待）を残し、末尾に **結果** を付ける。差分メモや解説は書かない。

## 流れ

1. `plans/<context>.md` に責務リストとケース表を書く（コード禁止）。
2. 人が表を承認する。
3. 承認後に `_test.go` を書く／更新する。
4. テスト実行後、`runs/_TEMPLATE.md` をコピーして結果を残す。

## 実行記録に書かないもの

- `go test -v` の全文ログ
- `coverage.out` / HTML（リポジトリでは ignore）

CI の合否はゲート、ここは計画どおり回した記録。
